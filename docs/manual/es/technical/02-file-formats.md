# Formatos de fichero

Todo lo que guarda OpenTabletop es texto que se puede leer y editar: YAML para los packs, JSON para los mapas.

## Packs

Un pack es una carpeta:

```
my-pack/
  pack.yaml              # id, nombre, versión, idioma base, licencia
  tables.yaml            # cualquier número de ficheros YAML o JSON con definiciones
  travel.yaml
  maps/
    frontier.otd.json    # mapas de ejemplo que lista un sistema (maps:), no definiciones
  locales/
    es/tables.yaml       # traducciones, con la misma estructura que los ficheros que traducen
```

`pack.yaml`:

```yaml
id: my-pack # minúsculas, dígitos y guiones
name: Mi pack # o { en: My pack, es: Mi pack }
version: 0.1.0
format: 11 # el formato de pack para el que está escrito (abajo)
locale: es # el idioma base
license: CC-BY-4.0 # consulta «Packs» para el contenido de uso personal
attribution: 'Basado en … de …'
dependencies: { core: ^0.1.0 } # packs cuyas tablas usa el tuyo
```

**`format`** dice para qué **formato de pack** se escribió el pack: qué significa su sintaxis. Cuando una versión nueva de OpenTabletop hace que el mismo YAML signifique otra cosa, el formato sube. Por ahora, mientras los formatos sigan cambiando, **un pack escrito para un formato anterior no se lee**: las aplicaciones lo dicen donde listan packs y sistemas (**Sin leer: escritos para un formato de pack anterior**, con **Descargar .zip** para guardarlo y **Borrar**), y hay que llevarlo al de hoy (la tabla de abajo dice qué cambió). Una copia tuya de un pack incluido que esté en un formato anterior no tapa al incluido: mientras tanto se usa ese. Los packs nuevos (**Nuevo pack** en el Oráculo, **Nuevo sistema** en Sistemas) se escriben para el de hoy; sin `format`, un pack se lee como de hoy. Un pack escrito para un formato más nuevo del que lee tu versión recibe un aviso: actualiza OpenTabletop. Los formatos hasta ahora:

| Formato  | Qué cambió                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                              |
| -------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 1        | El primero.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                             |
| 2        | Una comprobación que ninguna tabla resuelve solo detiene el viaje con `pause: true`. En el formato 1, una sin tabla ni efectos lo detenía siempre.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                      |
| 3        | Las reglas de viaje **no tienen un día integrado**: ni `day:` (alba, anochecer, la acción de la noche), ni el momento `day-start`, ni los datos `daylight`, `dawn` o `nightfall`, ni los pasos `time: dawn` / `nightfall`, ni acampada, descanso o marcha que el sistema no declare, ni `lost` integrado. Un sistema dice cuándo empiezan los viajes (`travel.start`), qué hace el grupo cuando no puede marchar (`travel.halt`), cuándo puede marchar (`actions.march`) y nombra sus momentos con horas (`'06:00'`) o partes del día del calendario ([Tipos: Reglas de viaje](07-kinds.md#reglas-de-viaje)).                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                           |
| 4        | **Marchar es una acción como las demás**: una acción mueve al grupo con un paso `travel.move` (`march: { do: [{ travel.move: destination }] }`; en el formato 3, `actions.march` solo decía cuándo valía la marcha integrada, con `when` / `unless`), las acciones tienen parámetros (`params`, y `do:` con `with:`), y el viaje sigue por sí solo con `travel.onward` (`onward: { do: march, with: { until: destination } }`). Los pasos `speed` y `advance` son `travel.speed` y `travel.advance`. ([Tipos: Reglas de viaje](07-kinds.md#reglas-de-viaje))                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                            |
| 5        | **Cada referencia dice qué es**: un momento, un bloqueo, una acción o una comprobación se escriben por su nombre completo, `subsistema.id` (`at: trip.hex-enter`, `on: time.day-end`, una parte del día `time.part.morning`, una acción `actions.camp`; `blocks: [travel.move, actions.forage, modes.horse]`; `do: actions.march`, `halt: { do: actions.camp }`, `roll: checks.ENCOUNTER`, `ask: params.how`, `travel.mode: modes.boat`; `time:` y `limit:` toman `time.<división>.<parte>`; el límite de una hoja que es otro de sus valores, `max: '{{self.values.maxHealth}}'`). En el formato 4 eran ids sueltos (`at: hex-enter`, `do: march`, `blocks: [travel, mode.horse]`, `time: part.morning`, `max: '{{maxHealth}}'`). Los valores que se comparan en las condiciones siguen cortos (`trip.connections: road`), y `moment` también se ve por el nombre completo (`trip.moment: actions.rest`). **Las referencias a las definiciones de un pack** también dicen su kind, con el pack delante cuando es de otro: `table: table.ruins`, `resolve: oracle.ford`, `generator: generator.npc`, `modes: [roll-modes.advantage]`, `cancels: roll-modes.disadvantage`, `travel: travel-rules.default`, `sheet: sheet.companion`, `weather: [weather.sky]`, `turn: core/table.faction-turn`, `aliases: { table.twist: core/table.twists }` (en el formato 4, `table: ruins`, `travel: travel-rules.default`, `core/faction-turn`). ([Sintaxis: Momentos](09-syntax.md#momentos), [Ids y referencias](09-syntax.md#ids-y-referencias)) |
| 6        | **Las comprobaciones de un momento se deciden una a una**, en el orden en que las listan las reglas, cada una justo antes de tirarla: su `when` / `unless` ven lo que fijaron las anteriores (el clima recién tirado, valores del día, `effects`). En el formato 5 se decidían todas a la vez al llegar el momento, así que una después de la del clima aún veía el clima de ayer. ([Tipos: Reglas de viaje](07-kinds.md#reglas-de-viaje))                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                              |
| 7        | **El `roll:` de un paso deja en espera el resto de su acción** hasta que se resuelve (y a **Continuar**, si pausa), como las comprobaciones del propio momento de la acción: los pasos siguientes ven su resultado. En el formato 6 se resolvía al acabar la acción, así que los pasos siguientes no lo veían. **Solo duran el día los valores que declara el sistema** (y el clima): en el formato 6 también duraba cualquier nombre acabado en `Modifier` o `Impossible`, así que decláralos en los `values` de las reglas (`fordModifier: { name: Modificador del vado }`). ([Acciones y pasos](10-actions-and-steps.md#otras-acciones-y-comprobaciones-do-y-roll))                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                  |
| 8        | **Lo que lleva el grupo es de su propia hoja o de sus personajes**: desaparecen los `resources` de las reglas de viaje y los `resources` de los bindings (`carried`, `share`); la comida, el agua o las antorchas son valores de la hoja del grupo (`party.values.food`, con su `default`, su `min` y su `max`) u objetos (`party.items.ration`, los del propio grupo y los de sus personajes juntos, repartidos según el `items.share` de la hoja, y un personaje nuevo lleva su `items.start`). Lo que llegó a un límite se nombra entero: `trip.below: party.values.food` (en el formato 7, por su id: `trip.below: food`), y también `trip.spent` / `trip.gained` (`trip.spent.party.items.ration`).                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                |
| 9        | **Lo que pasa cuando se llena un reloj de progreso es una reacción del mundo** (`kind: world`, nombrado por `world:` en el sistema): `on: world.clocks.<id>.full` con pasos `say`, `roll` y `effects`. Un reloj solo guarda qué es de él, `then` (en el formato 8 tenía `onFull` con `description`, `resolve`, `effects` y `then`: sube su `then` al reloj, y lo demás a una reacción). ([Tipos: Las reglas del mundo](07-kinds.md#las-reglas-del-mundo))                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                               |
| 10       | **Lo que no cabe se queda atrás, o espera sitio**: donde una hoja no admite más (`over: refuse` en un lugar, un contenedor o su nuevo total `items.room`), lo que da un efecto sin sitio libre entra hasta donde quepa, y el resto se queda atrás (lo dice el diario) o, con `items.full: ask` en la hoja, espera en la tarjeta del personaje a que el jugador haga sitio, y el viaje con él. En el formato 9 se quedaba con el personaje en ningún lugar. No hay nada que reescribir: pon `full: ask` donde se quería lo de antes. ([Tipos: Hojas](07-kinds.md#hojas))                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                 |
| 11       | **Donde está el grupo es un sitio**, sea cual sea el mapa (hoy un hex; más adelante una sala o un punto): lo que las tablas y condiciones leen de él es `place.*` (`place.terrain`, `place.tags`, `place.danger`, `{{place.danger}}`), los efectos que crean sitios en él son `place.pois.<id>`, el momento de entrar en él es `trip.place-enter`, un `travel.move` al siguiente es `place`, y la cuenta del viaje es `trip.places`. En el formato 10 eran `place.*`, `hex.pois.<id>`, `trip.hex-enter`, `hex` y `trip.hexes`: reescríbelos. ([Sintaxis](09-syntax.md))                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                 |
| 12       | **Lo que une dos lugares es una conexión**: los tipos de conexión de las reglas de viaje son `connections:` (`road`, `river`, más adelante puertas y similares) y las condiciones leen los del paso como `trip.connections` (en el formato 11, `edges:` y `trip.edges`).                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                |
| 13       | **El tiempo de una conexión se suma al paso**: los minutos `extra` de un tipo de conexión se tardan además del tiempo de siempre del paso (`ford: { extra: 60 }`, una hora más); en el formato 12, sus `minutes` sustituían al tiempo del paso.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                         |
| 14 (hoy) | **Los km de una casilla**: la escala de las reglas de viaje es `travel.cellKm`, los km que mide una casilla, hex o cuadrada (en el formato 13, `travel.hexKm`). Renómbralo. Nuevos a la vez, sin cambiar nada antiguo: `travel.diagonals` y `travel.cutCorners`, para mapas de casillas cuadradas.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                      |

Un fichero contiene una definición, varias separadas por `---`, o una lista. Cada definición tiene un `kind`: `table`, `oracle`, `generator`, `deck`, `roll-modes` y, para los viajes y el mundo, `travel-rules`, `bindings`, `calendar`, `weather`, `sheet`, `factions`, `clocks` y `system` (cada uno, con un ejemplo entero: [Tipos de definición](07-kinds.md); toda la sintaxis: [Sintaxis](09-syntax.md)). Sus campos se explican también en [Referencia YAML](../oracle/06-yaml.md), [Dados, variables y contexto](../oracle/08-dice-and-templates.md) y [Conectar tablas con mapas y viajes](../oracle/07-connecting.md).

Las reglas exactas (qué campos, qué valores) están definidas en el código, en `packages/oracle-engine/src/definitions/schema.ts` y `packages/travel-engine/src/rules.ts`; las aplicaciones comprueban cada fichero contra ellas al cargarlo e indican los problemas con su línea.

Un **.zip de packs** (el **Exportar .zip** de la Oráculo para un pack, el **Exportar como .zip** de la aplicación Sistemas para un sistema y todos los packs que necesita) tiene cada pack en su carpeta en la raíz (`grey-marches/pack.yaml`, `core/pack.yaml`…), primero el pack propio del sistema. Al importarlo se lee cada carpeta con un `pack.yaml`, a cualquier profundidad, cada fichero va a la carpeta de pack más cercana por encima, y solo los ficheros `.yaml`, `.yml` y `.json`; cada pack toma el nombre del `id` de su manifiesto, se llame como se llame su carpeta. Así que una carpeta de pack que comprimas a mano también se importa.

Una **exportación** (el **Exportar…** del selector de aplicaciones: packs, campañas con sus mapas y viajes, personajes, elegidos uno a uno) es un .zip con sus packs en `packs/<id>/` y lo demás al lado; importarla en la Oráculo toma solo sus packs. Ver [Copias de seguridad y exportaciones](05-backups.md#el-fichero-de-una-exportación).

## Mapas: OpenTabletop Data (`.otd.json`)

Mapa guarda los mapas como **paquetes OTD**, un formato JSON pensado para compartirse entre herramientas:

```json
{
  "otd": "0.2.0",
  "campaign": { "id": "…", "type": "campaign", "name": "…", "system": "…", "time": 4320 },
  "maps": [{ "id": "…", "type": "map", "grid": { … }, "terrains": [ … ],
             "hexes": { "3,4": { "terrain": "forest", "tags": ["ruins"], "region": "…" } },
             "paths": [ … ], "ext": { "map": { … } } }],
  "pois": [ … ], "parties": [ … ], "characters": [ … ], "log": [ … ], "state": { … }
}
```

- `campaign` es la campaña a la que pertenece el mapa (su id, nombre y `noteRef`, su `system`, la hora del reloj del mundo, y en `ext.map.packs` los packs que añade a los de su sistema): el reloj del mundo, su clima, las facciones y el Oráculo de abajo son de la campaña, así que el fichero se basta a sí mismo. Un fichero guardado antes de las campañas no la tiene: el mapa se abre con una campaña propia, hecha con lo que trae el fichero. Cuando este navegador ya tiene la campaña del fichero, abrirlo pregunta si unirse a ella, sustituirla o conservar la del fichero aparte ([Campañas](../map/01-getting-started.md#campañas)); los mapas de ejemplo de un sistema cuyos ficheros nombran una misma campaña se unen a ella sin preguntar, así que comparten un mundo (los dos mapas de las Marcas Grises).
- Los hexes van indexados por `"columna,fila"`. Un mapa de casillas cuadradas lo dice en su `grid`: `"kind": "square"`, y `"diagonals": true` cuando las casillas en diagonal también son vecinas ([Hexes o cuadradas](../map/01-getting-started.md#hexes-o-cuadradas)); sin `kind`, hexes, con su `orientation`. Un terreno marcado como **Suelo** lleva `"floor": true` (los muros se dibujan a partir de él, nunca se guardan); una región que se juega como un solo lugar, `"onePlace": true` en `ext.map.regions`, y durante un viaje esa sala es el lugar `area:<id de la región>` (en el diario, `travel.location`).
- Un **submapa** dice de dónde cuelga en `parent`: `{ "map": "hollowhills1", "place": "10,8", "entrance": "0,3", "kind": "way-in" }`, el id del mapa de arriba, su lugar en él, su propia entrada y el tipo de conexión que es el camino ([Submapas](../map/13-sub-maps.md)). Mientras un viaje sigue en otro mapa del árbol, el `ext.map.away` del grupo lo nombra. Durante un viaje, un lugar de otro mapa se escribe `@<mapa>/<hex>` (`@hollowhills1/10,8`): en el diario, y como `place.id` mientras el grupo cruza un camino.
- Los PDI, el grupo y los tokens (como personajes con `location`) son entidades propias; el diario de un viaje está en `log`.
- Los personajes del grupo (cuando su sistema tiene una [hoja](07-kinds.md#hojas)) también son personajes, listados por id en los `members` del grupo, con `kind: pc`, sus valores como `stats`, sus etiquetas, y lo que solo lee el motor de personajes (su hoja, estados, relaciones, objetos y lugares propios) en `ext.character`. Un mapa puede traer así su compañía antes de que empiece ningún viaje: el mapa de ejemplo de las Marcas Grises tiene a Kael, Mara y el viejo Tobin.
- Las facciones de la campaña son facciones OTD (sus valores como `stats`, su hoja en `ext.character`, los hexes que tienen en este mapa en `ext.map.territory`, su página en la aplicación de notas como `noteRef` y la nota corta del máster como `notes`), y `state.factions` dice de qué sistema vinieron y cuándo fue el último turno del mundo.
- `state.oracle` es el estado del Oráculo de la campaña (mazos, resultados de una sola vez, valores fijados); Mapa guarda su historial de tiradas a mano en `ext.map.oracleHistory`.
- `ext.<herramienta>` guarda los datos propios de cada herramienta (Mapa guarda iconos, rótulos, estilos y su configuración de impresión en `ext.map`; los ficheros escritos antes de que el sistema fuera de la campaña tienen ahí el `system` del mapa y los `packs` que añadía, que se leen como los de su campaña; el `ext.map.system` del grupo es el sistema con el que empezó su viaje). Las herramientas conservan intacto lo que no entienden al guardar. Los ficheros guardados cuando Mapa se llamaba Hexmapper (hasta la v0.25.0) tienen sus datos en `ext.hexmapper`: se leen como `ext.map`, y se guardan como `ext.map` desde entonces.

**Ficheros de personajes.** El **Exportar** de la aplicación Personajes escribe el mismo formato solo con `characters` (cada uno con su `noteRef`), y su **Importar…** lee los personajes de cualquier fichero así, también de un mapa:

```json
{
  "otd": "0.2.0",
  "characters": [
    {
      "id": "viejo-tobin",
      "type": "character",
      "name": "Viejo Tobin",
      "kind": "pc",
      "noteRef": "Personajes/Viejo Tobin",
      "stats": { "health": 4 },
      "ext": { "character": { "sheet": "mi-juego/companion" } }
    }
  ]
}
```

La descripción completa está en `docs/otd.md`, y el esquema en `packages/schema` (también puede generar un JSON Schema).

## En el navegador

Tus packs viven en el almacenamiento local del navegador con la clave `opentabletop.userPacks` (una lista JSON de packs con sus ficheros), el plantel de la aplicación Personajes con `opentabletop.characters` (cada entrada un personaje con sus notas y dónde juega; un grupo tiene `members`, los ids de sus personajes, y el grupo de un viaje o un mapa nombra el grupo del plantel que es, `partyRef`), y los viajes de la aplicación Viajes con `opentabletop.travel.trips` (versión 10: cada uno nombra la campaña en la que se juega, `campaign`; los guardados antes tienen una propia, con el id del viaje; un viaje guardado antes de la versión 10 pasa sus antiguas provisiones a los valores del mismo id de la hoja del grupo, y se pierde una provisión que llevaban sus personajes); los mapas y las campañas viven en su biblioteca IndexedDB (una campaña, versión 4, guarda su `system` y los `packs` que añade, su reloj del mundo, su clima, las hojas de las facciones, el Oráculo, qué viaje se jugó en ella el último, `playing`, y los relojes que se llenaron mientras ese viaje no estaba, esperándolo, `moments`; un mapa, versión 29, guarda las conexiones dibujadas entre lugares (`connections`: cada una con los dos lugares que une, su tipo, nombre, etiquetas y valores; `stats` en un fichero OTD, como los de un hex), nombra su campaña (las antiguas provisiones de su viaje pasan a los valores de la hoja del grupo, como las de Viajes; el diario y los totales de su viaje dicen lugares donde los antiguos decían hexes, como también los viajes de Viajes) y no guarda sistema propio: uno guardado antes le pasa su sistema y sus packs a su campaña al abrirse, si la campaña no tiene). Exporta los packs en .zip y guarda los mapas en fichero para conservarlos.
